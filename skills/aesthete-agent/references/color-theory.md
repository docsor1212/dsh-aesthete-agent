# 配色理论速查(aesthete-agent)

## 为什么用 OKLCH

RGB/Hex 是"给机器的坐标"——数值相近的颜色看起来差很远,看起来相近的颜色数值差很远。OKLCH 是感知均匀色彩空间:L(明度)、C(饱和度/chroma)、H(色相)每个轴都对应人眼感受。**凡是"把颜色变亮/变灰/转色相"的操作,在 OKLCH 里做等量移动,视觉上就是等量变化**;在 RGB 里做就是随机结果。工程实践普遍推荐 oklch;CSS 全主流浏览器 2023 起支持 `oklch()` 直接书写。本 skill 的 harmony/mutate 全部在 OKLCH 内运算(Ottosson 公式,公有领域)。

经验值:sRGB 色域内 C 上限约 0.15-0.30(随 L/H 变化,脚本自动 gamut_fit 收缩);UI 主色 C 取 0.10-0.19,背景 C ≤ 0.02,文字 C ≤ 0.01。

## 七种谐和规则(harmony 命令)

| mode | 色相偏移 | 气质 | 适用 |
|---|---|---|---|
| monochromatic | 0(只动 L/C) | 克制、安全 | 正文多的页面、专业文档 |
| analogous | ±30° | 和谐、有氛围 | 落地页、封面 |
| complementary | +180° | 张力、醒目 | CTA、运动品牌、要点强调 |
| split-complementary | +150°/+210° | 互补的柔和版 | 想要张力但怕刺眼 |
| triadic | +120°/+240° | 丰富、均衡 | 图表分类色、儿童内容 |
| tetradic/square | +90° 均布 | 最丰富、最难驾驭 | 信息密集的可视化 |

规则只管色相,不管好坏——**明度架构(下节)才是专业感的主要来源**。

## 明度架构(专业感的 80%)

专业配色与业余配色的最大差异不是色相选择,而是明度分层:
1. 一块安静的**底**(L≈0.95-0.98 浅色 / 0.20-0.25 深色,低 C);
2. 一档可辨的**面板/表面**(与底差 ΔL≥0.05);
3. 中明度**主色**(L≈0.50-0.68,承载品牌);
4. 极深/极浅的**文字**(与底对比≥4.5:1);
5. 高饱和**点缀**(全页 ≤10%,通常只给 CTA/图表强调)。

`roles` 命令按此启发式自动分配;`slop` 的 FLAT-LIGHTNESS 检查(L 极差 <0.25)就是抓"全糊在一起"的失败。

## 60-30-10 法则

60% 主导色(底)· 30% 次要色(结构)· 10% 点缀色(强调)。室内设计行规,无正式文献出处(House Beautiful 2025 / Apartment Therapy 均作行规转述),但与"点缀要稀缺才有力"的视觉原理一致。变体:30% 可用材质/纹理替代色相。

## WCAG 对比度(W3C WCAG 2.2 一手源核实)

- 公式:ratio = (L1+0.05)/(L2+0.05),L 为线性化相对亮度(0.2126R+0.7152G+0.0722B,通道先做 sRGB 线性化:≤0.04045 除以 12.92,否则 ((c+0.055)/1.055)^2.4)。比值域 1:1 至 21:1,与色相无关。
- 阈值:正文 AA ≥ **4.5:1**;大字(≥18pt/24px,或 ≥14pt bold/18.5px)AA ≥ **3:1**;AAA ≥ **7:1**(大字 4.5:1);非文字 UI 组件/图形(SC 1.4.11)≥ **3:1**;logo/装饰性文字豁免。4.499:1 就是不合格,不四舍五入。
- 已知边界值可作自测:`#767676` on `#FFFFFF` = 4.54:1(过);`#777777` = 4.48:1(不过)。
- 图表/信息图里每块"有意义的色块"与背景之间按 3:1 查。

## 色觉无障碍

人群比例:男性 ~8% 红绿色弱(protan/deutan),女性 ~0.5%;蓝黄色弱(tritan)<1%。
- `blind` 命令用 Machado et al. 2009(1.0 强度)矩阵模拟,输出模拟后各色 + 最小两两分离度变化;<0.07(oklab 距离)标 COLLISION RISK。
- 图表防呆三招:① 明度阶梯优先(明度差是不依赖色觉的通道);② 形状/线型/标注冗余编码;③ 红+绿、青+灰永不并置作唯一区分。

## 色彩语义速查(写色彩命令/与用户沟通用)

| 色 | 正向联想 | 场景慎用 |
|---|---|---|
| 红 | 紧迫、热情、警示 | 医疗/财务"下降"语义冲突;大面积刺激 |
| 橙 | 活力、亲和、价廉 | 高端感弱 |
| 黄 | 明快、注意、乐观 | 浅底上文字不可读;大面积刺眼 |
| 绿 | 健康、生长、通过 | 金融"下跌"文化差异(中式股市红涨绿跌) |
| 蓝 | 信任、专业、冷静 | 食欲场景差;**是最容易被模型滥用成"默认色"的颜色** |
| 紫 | 奢华、神秘、创意 | **AI 生成物第一眼标签,慎作主色**(见 anti-slop) |
| 棕 | 朴实、温暖、自然 | 亮度控制不好显脏 |
| 粉 | 柔和、年轻 | 专业医疗语境慎大面积用 |
| 黑/白/灰 | 高级、秩序 | 灰底灰字对比度重灾区 |
| 金 | 华贵、颁奖 | 易俗;小面积点缀才稳(用户既有审美铁律:禁金丝金边) |

文化差异提醒:颜色语义随语境翻转(股市红绿、婚礼白红、丧事紫白……),面向公众的交付先确认受众。

## 图表/幻灯片专用映射

- **分类色**(categorical):triadic/tetradic 生成 + 明度阶梯冗余;每色与白底 ≥3:1。
- **序数色**(sequential/热图):单色相 L 阶梯 0.95→0.25(`ramp` 命令);diverging 用互补双端 + 中性明色中点。
- **幻灯片**:背景用 bg,标题用 text,强调线条/数据高亮用 accent(≤10%),每页新增颜色不超过 1 个。

## 明度阶梯的端点降饱和规则

做 ramp 时接近纯白/纯黑的端点**收饱和度**,不为数学均匀硬保高 chroma——端点高饱和显脏且刺眼。`ramp` 已内置:chroma 缩放 = clamp(min((L-0.02)/0.30, (0.98-L)/0.30, 1))。

## 暗色主题是重新构图,不是反色

机械把浅色主题取反会得到刺眼的纯黑底+荧光字。正确做法(写入 CSS 变量架构):
```css
:root { --c-bg:#F7F5F0; --c-text:#1E1B17; --c-accent:#BC6C25; }
[data-theme="dark"] { --c-bg:#1E1B17; --c-text:#F0EAE2; --c-accent:#DDA15E; }
```
暗色下:海拔用"亮一档的面"表达(表面比底亮 ΔL≈+0.05-0.08),accent 常需提亮一档保对比;永不用纯黑 #000/纯白 #FFF 作底/字。整页翻转=改一个属性,不做组件内三元判断。
