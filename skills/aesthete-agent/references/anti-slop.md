# AI-slop 反面清单(写否定清单/跑 slop 检测用)

## 证据链(为什么模型配色差)

1. **中位数陷阱**:LLM 是统计模式匹配器,模糊指令下输出训练数据的中位数——而前端教程的中位数是紫/靛蓝(Tailwind 演示色的历史偶然被教程海量复制,成为"现代网页"的刻板印象)。
2. **模型看不见颜色**:ColorBench 基准(arXiv:2504.10514,NeurIPS 2025)系统评测视觉语言模型的色彩感知/推理/鲁棒性,结论:模型更大略好,但整体色觉理解仍然有限——模型在"操作颜色的文字",不是"看着颜色设计"。
3. **忽视可读性约束**:AI 生成的颜色组合经常过不了 WCAG 对比度,设计社区对此已有普遍共识并主动规避"一眼 AI"配色。
4. **修法有效**:显式指定色彩/字体维度、参照具体美学、推理期否定禁用项、一次出多方案。

## 版式黑名单(配色相关项)

1. 暖奶油底(≈#F4F1EA)+ 高对比衬线大标题 + 陶土色点缀——当前 AI 三大默认长相之一;
2. 近黑底 + 单一荧光绿/朱红点缀——同上;
3. "大数字+渐变点缀+深色背景"是最泛滥的 hero 模板。✅ 替代:数字保留但底换浅纸+幽灵数字描线,渐变换实色块。

注:这三条是**默认即嫌疑**——brief 明确要求时照做,brief 没约束时别把自由花在默认上。

## 否定清单模板(直接抄进设计 prompt)

```
禁用:Tailwind 默认蓝/靛/紫家族(#3B82F6/#6366F1/#8B5CF6 及其渐变组合)
禁用:紫→粉/紫→蓝渐变背景
禁用:Inter/Roboto 配这套颜色(换有性格的字体)
禁用:所有颜色同明度
要求:参照美学「<一句话,如:中药铺抽屉:深褐、米黄、朱砂印泥红」
要求:正文对比度≥4.5:1,图表色块≥3:1,红绿不同时作唯一区分
```

推理期否定是模型可执行的操作(实证有效),写出来就比不写强。

## 通用反模式

- **不要在输入未变时重复同一分析或已被拒绝的调用** —— 重试前先改变一个输入(换 seed/换板/换语域)或先解除阻塞;同输入重跑 = 重复烧钱,结论不会变。
- **不要替用户点名** —— 候选 ≥2 时出对比页让用户选,替用户决定 = 白做。
