# 配色法则卡(五镜审核的速查面)

每条法则都可操作、可举证。写设计 prompt / 跑五镜自审时直接引用法则名。

## 方向类

- **「Brief 即法律」**:用户钉死的美学/年代/材质/字体/色板是绑定约束,即使它与别的建议冲突也照办。把明确的 brief 拧向自己的口味 = 失败。
- **「哲学先行」**:先命名 1-2 词的美学运动并写一句宣言,再动手。"Chromatic Silence"式的名字逼出具体选择;说不出宣言 = 还没想清楚。
- **「中位数陷阱」**:模糊指令下,模型输出训练数据的中位数——而前端教程的中位数是紫/靛蓝。修法 = 参照美学 + 显式维度 + 否定清单,三件套缺一不可。

## 色彩类

- **「角色,不是色块袋」**:配色是角色体系——底/面、主/次文本、动作/焦点/选中、边框/分隔、成功/警告/错误/信息、数据类别——不是一把抓出来的 hex。→ `roles --semantic`
- **「稀缺即力量」**:点缀色的力量与面积成反比。最强的色应当拥有一块完整区域,而不是撒成碎片;10% 是脚手架不是法律,比例追随 brief。
- **「可测量与品味分离」**:对比度、色盲碰撞、明度跨度交给机器;好不好看留给上下文自审与用户。→ `score` / `lint_page` 只报机械发现,不判审美。
- **「端点降饱和」**:明度阶梯接近纯白/纯黑的端点要收饱和度,不为数学均匀硬保高 chroma——端点高饱和显脏且刺眼。→ `ramp`
- **「显式色优于透明叠加」**:宁可写明确色值,不用半透明叠加链——alpha 会让对比度随背景漂移,验证失效。
- **「暗色是重新构图」**:暗色主题 = 显式设计海拔与对比(面板比底亮、accent 提亮一档),不是把浅色主题机械反色;永不用纯黑/纯白作底与字。
- **「彩色面上的次级文字从色调派生」**:在彩色表面写次级文字,用前景/表面色相派生,不用发灰的通用灰。

## 流程类

- **「有界验证」**:完整做完 → 一轮批量检查 → 一轮批量修 → 最多再确认一次 → 停。开放式自检循环烧钱且产出更差。
- **「第二遍只精炼」**:想加新元素时停下来问——"怎么让已有的更像一件作品?"禁止"再加个滤镜/再画个形状"式修改。
- **「样张 + 点名」**:候选 ≥3 时,渲染命名样张让用户按名字挑,不要用文字描述色板让用户想象。→ `showcase` / `make_variants`
- **「视觉反馈回路是最高杠杆」**:盲改必翻车;一切以截图与渲染实测证据收敛。→ `render_probe.js` + `lint_page --render`
- **「新项目 = 新提问」**:别把上次会话的视觉方向当这次的默认;可作建议,须确认。
